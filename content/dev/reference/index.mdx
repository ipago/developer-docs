This reference is generated from the OpenAPI document the iPago API publishes, on every docs build, so it lists exactly what the API accepts and returns. It covers the three public surfaces: the **Developer API** (API keys), the **Storefront API** (baskets and public store data) and the **Game API** (the delivery queue for game server plugins).

## OpenAPI document

<a href="/openapi.json" download="ipago-openapi.json">Download openapi.json</a> to generate a client or import the API into a tool such as Postman or Insomnia. It contains the operations documented here, with tags and security schemes.

The API also serves its own document live at [https://api.ipago.io/openapi.json](https://api.ipago.io/openapi.json). That one describes every route the server runs, including internal routes for the iPago dashboard that are not part of the public API.

## Authentication

| Credential | Sent as | Used by |
| --- | --- | --- |
| API key | `Authorization: Bearer sk_live_...` (or `sk_test_...` in test mode) | Developer API. Each operation names the scope the key needs. |
| Server token | `X-iPago-Server-Token: ...` | Game API. One token per game server, created in the dashboard. |
| Basket token | `X-Basket-Token: ...` | Basket operations. Returned once, when the basket is created. |
| None |   | Public storefront reads and basket creation. |

A test-mode API key (`sk_test_...`) only sees test-mode data, and test-mode payments run on separate test payment credentials, so no real money moves.

## Errors

Every error response has the same shape:

```json
{
  "error": {
    "type": "invalid_request_error",
    "code": "resource_missing",
    "message": "No such order: ord_123",
    "param": "order",
    "request_id": "req_6f1c..."
  }
}
```

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `error.type` | `string` | Yes | Broad category of the error. |
| `error.code` | `string` | Yes | Stable, machine-readable reason. Branch on this. |
| `error.message` | `string` | Yes | Human-readable explanation. May change. |
| `error.param` | `string` | No | The parameter the error is about, when there is one. |
| `error.request_id` | `string` | Yes | Quote it when you contact support. |

| Status | Meaning |
| --- | --- |
| `400` | The request is invalid: a missing or malformed parameter, or a rule the request breaks. |
| `401` | The credential is missing, invalid or revoked. |
| `403` | The credential is valid but not allowed to do this, for example a missing scope. |
| `404` | The resource does not exist, or is not visible to this credential. |
| `409` | The request conflicts with the resource's current state. |
| `429` | Too many requests. Back off and retry. |
| `500` | Something went wrong on iPago's side. |
| `503` | A dependency is temporarily unavailable. Retry later. |

## How this page is built

The API generates `apps/api/openapi.json` from its route schemas (`cd apps/api && pnpm -s openapi:gen`). The docs build reads that file and writes these pages, so a change to the API reaches the reference in the same commit. Which operations are public is listed in one place, `apps/docs/lib/reference/catalog.mjs`.
