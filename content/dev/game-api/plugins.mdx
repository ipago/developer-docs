You rarely need to write the [queue loop](/dev/game-api/delivery-queue) yourself.
A game server can receive purchases in one of two ways, chosen when you add it
under **Integration → Game servers**:

| Connection | Who does the work | You need |
| --- | --- | --- |
| **Plugin** | A plugin on your server polls the Game API, runs the commands, and confirms them. | The plugin and the server's token. |
| **RCON** | 2Pay's own worker connects to your server's RCON port and runs the commands. | RCON enabled on the server, and its host, port and password. |

Available plugin today: **Minecraft** (Paper and Spigot 1.20 or newer). Every
other game that speaks RCON can use the RCON connection.

## Mapping products to commands

What a purchase *does* on your server is defined by the **commands you attach
to the package** in the panel: edit the product and choose **Game server** as
its delivery method. Each command has:

| Setting | Meaning |
| --- | --- |
| Kind | **Online**: needs the player connected (give an item, open a crate). **Offline**: runs whether or not they are (grant a permission, add currency). |
| Command | The console command, up to 512 characters, with `{username}` and `{uuid}` placeholders. |
| Delay | Seconds to hold the command back after purchase, 0 to 86400. |
| Slots | Free inventory slots the player needs, 0 to 64. Only plugins check this. |
| Servers | The servers it runs on. Name none and it runs on every server of the store. |

A package can carry up to 25 commands. Buying a quantity of 3 queues each
command 3 times.

## Minecraft

The official plugin for Paper and Spigot servers. It polls the Game API, runs
each command on the server's main thread, and confirms only the commands that
actually ran. Your server only makes outbound HTTPS calls, so there is nothing
to open in your firewall.

### Requirements

- Paper or Spigot **1.20 or newer** (it uses the Bukkit API).
- **Java 17** or newer.
- Outbound HTTPS to `game.2pay.gg`.

### Install

1. In the panel, open **Integration → Game servers**, choose **Plugin** as the
   connection, add the server, and copy its token. It is shown once. Add it in
   test mode first if you want to [try it safely](#testing-before-you-go-live).
2. Put `2pay-minecraft-<version>.jar` in your server's `plugins/` directory.
3. Start the server once. That creates `plugins/2pay/config.yml`. Until a token
   is set, the plugin stays idle and logs a reminder.
4. Paste the token into `token:` in `plugins/2pay/config.yml`.
5. Restart the server. The log shows `Delivering 2pay purchases from https://game.2pay.gg/v1`,
   and the first poll happens a few seconds later.
6. Run `/2pay status` in the console to confirm it is talking to 2Pay.

### Configuration

`plugins/2pay/config.yml`:

```yaml
# The server token from the 2pay panel, under Integration > Game servers.
token: "srv_live_paste-yours-here"

# The Game API base URL. Change this only to point at a sandbox or a local instance.
base-url: "https://game.2pay.gg/v1"

# Seconds to wait when the API does not say otherwise.
fallback-interval: 60

# Log every command before it runs.
log-commands: false
```

| Key | Default | What it does |
| --- | --- | --- |
| `token` | none | The server token from the panel. Without it the plugin stays idle and says so. |
| `base-url` | `https://game.2pay.gg/v1` | Change only to point at a sandbox or a local instance. |
| `fallback-interval` | `60` | Seconds between polls when the API does not set the pace itself (minimum 5). Normally the API's `next_check` decides. |
| `log-commands` | `false` | Log every command before it runs. Useful while setting up, noisy afterwards. |

Changes take effect after a restart.

### `/2pay status`

Run it from the console, or in game with the `twopay.admin` permission (ops
have it by default). It reports:

- where the plugin is pointed (`2pay talks to https://game.2pay.gg/v1`),
- when it last completed a poll, or that it has not completed one yet,
- the last error, or `No errors.`

If no token is set it tells you to set `token` in `plugins/2pay/config.yml` and
restart.

### Online and offline commands

- **Online** commands wait until the buyer is connected to this server, and
  check they have the free inventory slots the command asks for.
- **Offline** commands run on the next poll whether the player is online or not.

`{username}` and `{uuid}` are filled in for the player who bought it. The API
does not carry a UUID, so the plugin resolves it from the game server.

A command is reported back to 2Pay **only after it has actually run**. If your
server was restarting, the player had no room, or the command failed, it stays
queued and comes back on the next poll. Nothing a player paid for is quietly
dropped. Once every command of a purchase has run, the delivery completes in
your panel and [`delivery.completed`](/dev/webhooks/events#deliverycompleted)
fires.

When the API is unreachable the plugin backs off, from 15 seconds up to 5
minutes between tries. When 2Pay rejects the token it logs a warning and waits
5 minutes before each new try, since retrying faster cannot fix a bad token.

### Testing before you go live

Add a server in **test** mode in the panel, use its `srv_test_` token, and make
a test-mode purchase. Test-mode tokens only ever see test-mode purchases, so you
can try the whole path without touching real orders.

### Troubleshooting

**"2pay rejected this server token" in the log.** The token is wrong, or it was
rolled in the panel. Roll it again under **Integration → Game servers** and
paste the new one into `config.yml`, then restart.

**The plugin polls, but nothing ever arrives.** Check the package in the panel:
it needs commands attached, and if those commands name specific servers, this
server has to be one of them. Also check the mode: a `srv_live_` token never
sees a test-mode purchase, and the other way round.

**An online command never runs.** The player has to be connected to this
server, under the exact name they typed at checkout, with enough free inventory
slots.

**A command runs but nothing happens in game.** The plugin runs commands exactly
as the console does. Type the same command into your server console with a real
player name. If it does not work there, it is the command or the plugin it
belongs to, not 2Pay.

**Nothing at all in the log.** Confirm the jar is in `plugins/` and that the
server loaded it (`/plugins` should list `2pay`), then check your server can
reach `https://game.2pay.gg`.

## RCON

Many game servers expose **RCON**, a remote-console protocol (Source RCON, which
Minecraft also speaks). With the RCON connection there is nothing to install and
no token: 2Pay's own delivery worker connects to your server, logs in, and runs
each owed command, then marks it delivered once the server has answered.

### Set it up

1. Enable RCON on your game server and set a password.
2. In the panel, open **Integration → Game servers** and add a server.
3. Choose **RCON** as the connection and enter the **Host**, **Port** and
   **RCON password**.
4. Press **Test connection**. 2Pay logs in and runs the harmless `list`
   command, and tells you whether it connected, the password was rejected, the
   server could not be reached, it timed out, or something answered that does
   not speak RCON.
5. Add the server.

The password is stored encrypted and is never shown again. To change the host,
port or password, remove the server and add it again.

### How commands run over RCON

- **Every command runs as soon as it is due.** RCON has no portable way to ask
  whether a player is connected, so **online** commands are not held back for
  the player; they run like offline ones. Inventory **slots** are not checked.
  The package **delay** is still honoured. Prefer commands that work for an
  offline player, or use the plugin.
- Commands for one server are sent in order over one connection, each with a
  5-second timeout. A command counts as delivered once the server has answered
  it. The delivery completes, and `delivery.completed` fires, when all of its
  commands have run.
- Delivery is at least once: if a command reaches the server but its answer is
  lost, it is retried and can run twice.

### Placeholders

`{username}` is filled in only when the buyer's name is plainly a name: 1 to 64
letters, digits, `_`, `-` or `.`. A name with anything else (a space, a `;`)
could inject arguments or a second command into the console, so that command is
never sent and fails at once. 2Pay does not know player UUIDs, so a command
containing `{uuid}` also fails at once over RCON. Commands and passwords must
not contain line breaks.

### Retries and failure

If 2Pay cannot connect, or a command errors, the command is retried on the
same [schedule as webhooks](/dev/webhooks/delivery-and-testing#retries): 15
attempts over about 38.5 hours. Later commands for the same server wait with it,
so they never overtake an earlier one. After the last attempt the command is
marked failed, its delivery is failed and
[`delivery.failed`](/dev/webhooks/events#deliveryfailed) fires, and an alert is
raised on 2Pay's side.

### Addresses and ports that are refused

2Pay connects from its own servers, so it refuses targets that would reach a
private network. The host must resolve **only** to public addresses: loopback,
private, link-local, CGNAT, multicast and other reserved ranges are refused,
including `localhost`. Sensitive ports are refused too, for example 22 (SSH), 25
(SMTP), 53 (DNS), 80 and 443 (HTTP), 3306 (MySQL), 5432 (Postgres) and 6379
(Redis). The check runs when you save, when you test, and again before every
connection, so a host name later repointed at a private address stops
receiving commands.

## Games without a plugin or RCON

Implement the [delivery queue](/dev/game-api/delivery-queue) loop yourself in
whatever language your server extends with. It is a small loop: `GET /queue`,
run online and offline commands, `DELETE /queue` to confirm.

Tell us which game you run at [support@2pay.gg](mailto:support@2pay.gg). Demand
directly shapes which plugins we build next.
