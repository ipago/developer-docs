---
title: Events
description: React to the checkout opening, closing, and payment outcomes in the browser.
---

The Checkout library emits browser events through `Checkout.on(name, callback)`.
Use them to drive your **UI**: show a spinner, redirect after success, re-enable a
button if the buyer closes the overlay. They are *not* a fulfillment signal.

```js
Checkout.on("open", () => console.log("checkout opened"));
Checkout.on("close", () => console.log("checkout closed"));
Checkout.on("payment:complete", (e) => console.log("paid", e));
Checkout.on("payment:error", (e) => console.error("failed", e));
```

Register listeners **before** calling `launch()`.

## Events

| Event | Fires when | Typical use |
| --- | --- | --- |
| `open` | The overlay has opened. | Disable the buy button, show that checkout is active. |
| `close` | The buyer closed the overlay (paid or not). | Re-enable the buy button, clean up UI. |
| `payment:complete` | A payment succeeded in the overlay. | Show a success state or redirect to a thank-you page. |
| `payment:error` | A payment attempt failed. | Show an inline error; let the buyer retry. |

## The golden rule

<Callout type="warn">
  Never grant a purchase from `payment:complete`. The browser is untrusted: a tab
  can close before the event fires, a network can drop, and a determined user can
  call your code directly. Use these events only to update what the buyer sees.
</Callout>

Fulfillment must be driven by the [`order.paid` webhook](/dev/webhooks/events),
which is signed, retried, and server-to-server. The correct division of labor:

| Concern | Source of truth |
| --- | --- |
| Updating the buyer's UI | Browser events (this page). |
| Granting items, ranks, keys, roles | The `order.paid` webhook and the [Deliveries API](/dev/developer-api/deliveries). |

## A complete handler

```js
Checkout.on("open", () => setBuying(true));

Checkout.on("close", () => setBuying(false));

Checkout.on("payment:complete", () => {
  // UI only. The webhook will actually fulfill the order.
  showToast("Payment received, your purchase is on its way!");
  window.location.href = "/thanks";
});

Checkout.on("payment:error", (e) => {
  showToast(`Payment failed: ${e?.message ?? "please try again"}`);
});

Checkout.init({ ident, closeOnComplete: true });
Checkout.launch();
```

For the matching backend flow, see
[Integrating](/dev/checkout/integrating#confirm-the-sale-server-side).
