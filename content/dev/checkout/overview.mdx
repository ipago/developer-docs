**Checkout** lets the purchase happen on your own website, launcher, or app.
iPago Sp. z o.o. is the seller to the player: the player pays iPago, and iPago
owes you the purchase price. You never touch card data. See
[Tax & VAT](/dev/developer-api/tax).

## Products come first

A checkout sells products you have **already defined in the panel at
[app.ipago.io](https://app.ipago.io)**, referenced by their `prod_` id. It does not
create products on the fly, so your catalog stays the single source of truth.

## The shape of an integration

An integration has two halves, and the split matters for security:

1. **Server side.** Your backend calls the
   [Developer API](/dev/developer-api/overview) `POST /v1/checkouts` with your
   secret key. iPago creates an order (`ord_` id) and returns a `client_secret`
   for the payment session.
2. **Client side.** The widget renders a short form you define (for example a
   username and an email), passes the values to a callback you write, and that
   callback asks your server for the `client_secret`. The widget then mounts the
   embedded card checkout on your page with it.

```
Browser (widget)                 Your server                     iPago
  │ buyer fills your form          │                               │
  │ createSession(values) ───────▶ │                               │
  │                                │ POST /v1/checkouts ─────────▶ │
  │                                │ ◀─ { id: ord_..., client_secret }
  │ ◀──────── { clientSecret } ─── │                               │
  │ embedded payment form mounts, buyer pays                       │
  │ buyer is redirected to your return_url                         │
  │                                │ ◀──────── order.paid webhook ─│
```

The widget never calls the iPago API and never sees a secret key.

## Confirm payments server-side, always

The browser is untrusted. Grant items, ranks or keys only from the
[`order.paid` webhook](/dev/webhooks/events), never from the buyer landing on
your return page.

## When to use Checkout

Use it when you already have your own site, launcher, or app and want the
purchase to complete there. If you would rather not build a frontend at all,
use the hosted [Webstore](/dev/webstores/overview), which is available today.
