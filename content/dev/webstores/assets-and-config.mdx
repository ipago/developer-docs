[Templates](/dev/webstores/templates) define structure; **assets** make a store
look and behave the way you want. And if you build templates for other creators,
a **config schema** lets them customize your work without editing code.

## Assets

Upload your own files in the panel under **Appearance → Assets**:

| Asset type | Use it for |
| --- | --- |
| **CSS** | All styling, layout, colors, fonts, responsive rules. |
| **JavaScript** | Interactivity, animations, third-party widgets. |
| **Images** | Logos, banners, backgrounds, icons. |

Reference an uploaded asset from a template with the `asset` helper, which
resolves to its served URL:

```html
<link rel="stylesheet" href="{{ asset('css/store.css') }}" />
<img src="{{ asset('img/logo.svg') }}" alt="{{ store.name }}" />
<script defer src="{{ asset('js/store.js') }}"></script>
```

Assets are served over a CDN, so prefer the `asset` helper over hardcoded paths,
it gives you correct, cacheable URLs.

<Callout type="info">
  Keep custom JavaScript scoped to presentation. The purchase flow and payment
  are handled by 2Pay; you do not (and should not) implement checkout logic in
  store JavaScript.
</Callout>

## Configurable templates

If you design templates for **other** creators (free or paid), you can expose a
set of options they can tweak from the panel, no code editing required. You
declare those options in a **config schema**, and their chosen values appear in
your templates as a `config` object.

### Declaring options

A config schema is a list of fields, each with a key, a type, a label, and a
default:

```json
{
  "fields": [
    {
      "key": "accent_color",
      "type": "color",
      "label": "Accent color",
      "default": "#5b2eff"
    },
    {
      "key": "hero_heading",
      "type": "text",
      "label": "Hero heading",
      "default": "Welcome to the store"
    },
    {
      "key": "show_featured",
      "type": "boolean",
      "label": "Show featured products",
      "default": true
    }
  ]
}
```

| Field type | Renders as | Value in templates |
| --- | --- | --- |
| `text` | A single-line text input. | String. |
| `textarea` | A multi-line text input. | String. |
| `color` | A color picker. | Hex string. |
| `boolean` | A toggle. | `true` / `false`. |
| `select` | A dropdown (add an `options` array). | The chosen option's value. |
| `image` | An image upload. | The asset URL. |

### Reading the values

Whatever the creator sets becomes available under `config`, keyed by your field
`key`:

```html
<style>
  :root { --accent: {{ config.accent_color }}; }
</style>

<section class="hero">
  <h1>{{ config.hero_heading }}</h1>
</section>

{% if config.show_featured %}
  {% include "partials/featured" %}
{% endif %}
```

Because every field has a `default`, your template renders sensibly even before a
creator changes anything.
