<Callout type="warn">
  Supplier settlement is a weekly self-billing purchase invoice, paid by the
  invoice due date. See [Invoice payment](/creators/getting-paid/invoices).
  `POST /v1/payouts`, `GET /v1/payouts`, and the field names on this page are the
  current API. They remain until the ledger change. They are not the invoice.
</Callout>

A **payout** is the object these routes return. Creating one requires
`payouts:write`. Reading requires `payouts:read`.

## Before calling `POST /v1/payouts`

Two things must be in place, both set up in the panel:

1. **A verified account.** Complete account verification (KYC). Until it is
   approved, `POST /v1/payouts` returns `403 account_not_verified`. This check
   applies to test keys too.
2. **A bank account.** Add the account invoice payments should go to under the
   account in the panel. Without it, a live call returns
   `400 payout_destination_missing`. Test-mode calls move no real money and do
   not need one.

## The payout object

```json
{
  "object": "payout",
  "id": "po_01M5NB7J2W4X6Z8A0C2E4G6J8K",
  "amount": 20000,
  "currency": "eur",
  "status": "paid",
  "destination": null,
  "bank_account": {
    "holder_name": "Blockworks Studio",
    "iban": "DE•• •••• 3000",
    "bic": "COBADEFFXXX"
  },
  "settlement_reference": "SEPA-2026-10-25-0042",
  "failure_reason": null,
  "created": "2026-10-24T10:00:00.000Z",
  "paid_at": "2026-10-25T08:30:12.000Z"
}
```

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Payout id (`po_`). |
| `amount`, `currency` | integer, string | The amount on the object, in minor units. |
| `status` | string | `pending`, `paid`, or `failed`. |
| `destination` | string \| null | The free-text `destination` you sent when creating it, if any. |
| `bank_account` | object \| null | Where a transfer would be sent: `holder_name`, `iban` (masked to the country code and last four digits), and `bic` (may be `null`). It is copied from the bank account on the account when the payout is created, so changing bank details later never redirects one already requested. `null` when no bank account was set, which only test mode allows. |
| `settlement_reference` | string \| null | The bank transfer reference, set when iPago marks the payout paid. Use it to match a transfer against a bank statement. |
| `failure_reason` | string \| null | Why the payout failed, when it did. |
| `created` | string | When the payout was requested. |
| `paid_at` | string \| null | When it was marked paid. |

## Lifecycle

- **`pending`**: requested. The amount is no longer included in `available` on
  [`GET /v1/balance`](/dev/developer-api/balance), so the same amount cannot be
  requested twice on this route. iPago emits `payout.created`.
- **`paid`**: iPago staff sent the bank transfer and recorded its
  `settlement_reference`. iPago emits `payout.paid`.
- **`failed`**: the transfer did not go through. The amount is included in
  `available` again and iPago emits `payout.failed`.

See [Events](/dev/developer-api/events) for the event payloads. `available` is a
field name on the current ledger route, not an amount iPago owes.

## Create a payout

```
POST /v1/payouts
```

| Parameter | Required | Description |
| --- | --- | --- |
| `amount` | yes | Positive integer in minor units. At most the `available` amount for that currency on `GET /v1/balance`. |
| `currency` | yes | Lowercase currency code, for example `"eur"`. |
| `destination` | no | Free text kept on the payout for your own records. It does not choose where the money goes. |

```bash
curl https://api.ipago.io/v1/payouts \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 0b9d6c3e-2f1a-4d8c-b7e6-9a5f4c3d2e1b" \
  -d '{ "amount": 20000, "currency": "eur" }'
```

Returns `201` with the payout in `pending`. Always send an
[Idempotency-Key](/dev/developer-api/idempotency): a retried request with the same
key returns the same payout instead of requesting a second one.

### Errors

| Status | `code` | When |
| --- | --- | --- |
| `403` | `account_not_verified` | Your account has not passed verification yet. |
| `400` | `payout_destination_missing` | Live mode, and no bank account is set in the panel. |
| `400` | `insufficient_balance` | `amount` is more than `available` for that currency on `GET /v1/balance`. `param` is `amount`. |
| `400` | `amount_too_small` | `amount` is below the minimum this route accepts. |
| `403` | `store_suspended` | The store is suspended. The route accepts calls again when the suspension is lifted. |
| `409` | `idempotency_key_reuse` | The `Idempotency-Key` was already used for a different request. |

## List payouts

```
GET /v1/payouts
```

| Parameter | Description |
| --- | --- |
| `status` | Only payouts in this state: `pending`, `paid`, or `failed`. |
| `limit`, `starting_after`, `ending_before` | [Pagination](/dev/developer-api/pagination). Results run oldest first. |

## Retrieve a payout

```
GET /v1/payouts/{id}
```

Returns the payout, or `404 resource_missing`.
