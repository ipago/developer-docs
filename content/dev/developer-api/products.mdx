title: Products

A **product** is something a buyer can purchase: a rank, a kit, an item bundle, a
license, a one-off donation perk. Products are created and priced in the panel at
[app.ipago.io](https://app.ipago.io); over the API they are **read-only**. You list
them and fetch them, you reference them by `id` at [checkout](/dev/checkout/overview),
and you read which product a given order line item maps to.

A **category** groups products for display. It mirrors the structure shown on
your Webstore.

## The product object

```json
{
  "object": "product",
  "id": "prod_01H9Z4ABCDEF",
  "name": "VIP Rank",
  "description": "Permanent VIP rank with cosmetic perks.",
  "active": true,
  "category": "cat_01H9Z3KQ",
  "price": { "amount": 999, "currency": "eur" },
  "type": "single",
  "billing_interval": null,
  "delivery_target": "game_server",
  "image_url": null,
  "created": "2026-05-02T08:14:00.000Z",
  "updated": "2026-06-20T19:03:11.000Z"
}
```

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Unique product id (`prod_`). |
| `name` | string | Display name, as set in the panel. |
| `description` | string | Long description. An empty string when none is set. |
| `active` | boolean | Whether the product is currently purchasable. Inactive products stay readable for historical orders. |
| `category` | string \| null | Id of the category it belongs to. |
| `price` | object | [Money](/dev/developer-api/conventions#money): `amount` (minor units) and `currency`. |
| `type` | string | `single` (one-time) or `subscription`. |
| `billing_interval` | string \| null | `month` or `year` for a subscription, `null` for a one-time product. |
| `delivery_target` | string | Your label for how the product is fulfilled: `game_server`, `manual`, or `none`. It is informational; the commands the [Game API](/dev/game-api/overview) runs come from the product's delivery configuration in the panel. |
| `image_url` | string \| null | Product image. |
| `created` / `updated` | string | ISO 8601 timestamps. |

<Callout type="info">
  You cannot override a price per request. Pricing, sales, and currency are panel
  settings. If you need a buyer-specific price, model it as a separate product or
  a coupon configured in the panel.
</Callout>

## List products

```
GET /v1/products
```

Returns a [paginated list](/dev/developer-api/pagination) of products, oldest
first. Requires the `products:read` scope, as do the category endpoints.

**Query parameters**

| Parameter | Description |
| --- | --- |
| `active` | `true` / `false` to filter by availability. |
| `category` | Restrict to one category id. |
| `limit`, `starting_after`, `ending_before` | [Pagination](/dev/developer-api/pagination). |

```bash
curl "https://api.ipago.io/v1/products?active=true&limit=50" \
  -H "Authorization: Bearer sk_live_..."
```

The response, with the product shortened:

```json
{
  "object": "list",
  "data": [
    { "object": "product", "id": "prod_01H9Z4ABCDEF", "name": "VIP Rank", "price": { "amount": 999, "currency": "eur" } }
  ],
  "has_more": false
}
```

## Retrieve a product

```
GET /v1/products/{id}
```

```bash
curl https://api.ipago.io/v1/products/prod_01H9Z4ABCDEF \
  -H "Authorization: Bearer sk_live_..."
```

Returns the full product object, or `404 resource_missing` if no product with
that id exists in the key's store and mode (test vs live).

## Categories

```
GET /v1/categories
GET /v1/categories/{id}
```

A category object:

```json
{
  "object": "category",
  "id": "cat_01H9Z3KQ",
  "name": "Ranks",
  "order": 1,
  "parent": null
}
```

Pass `?include=products` on either endpoint to embed each category's products
inline as a `products` array (up to 100 per category), which is handy when you
are rendering a full storefront in one pass. Without it, the `products` field is
absent.

```bash
curl "https://api.ipago.io/v1/categories?include=products" \
  -H "Authorization: Bearer sk_live_..."
```

## Keeping a local copy in sync

If you mirror the catalog locally (for a custom storefront, say), there are no
catalog events to subscribe to, so refresh on a schedule: a periodic full
`GET /v1/products` and `GET /v1/categories` pass is cheap, and the catalog
changes rarely. Do not refetch on every page view.
