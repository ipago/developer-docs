---
title: Ledger
description: Read GET /v1/balance and ledger entries. These names stay until the ledger change.
---

iPago keeps a double-entry ledger behind every sale, refund, dispute, and the
legacy payout routes. You can read the entries through the API. These routes are
read-only: money moves through checkouts,
[refunds](/dev/developer-api/refunds), and the routes under
[payouts](/dev/developer-api/payouts), never through direct writes.

**This is not how iPago pays you.** iPago owes the purchase price (suggested
retail price minus the margin) and pays it on a weekly self-billing purchase
invoice, by the invoice due date. See
[Invoice payment](/creators/getting-paid/invoices).

`GET /v1/balance` and the field names on this page are the current API. They
remain until the ledger change. The response is not the amount iPago owes the
supplier.

Both endpoints require the `ledger:read` scope.

## `GET /v1/balance`

```
GET /v1/balance
```

```bash
curl https://api.ipago.io/v1/balance \
  -H "Authorization: Bearer sk_live_..."
```

```json
{
  "object": "balance",
  "available": [ { "amount": 48210, "currency": "eur" } ],
  "pending": [ { "amount": 12500, "currency": "eur" } ]
}
```

There is one entry per currency, and currencies with nothing in them are left
out, so both arrays can be empty. Amounts are in minor units.

- **`pending`** and **`available`** are the two amount lists this endpoint
  returns today. They are legacy ledger figures from before weekly invoices.
- **`available`** can be negative after a later entry, for example a refund or a
  lost dispute booked on this ledger.

<Callout type="info">
  VAT on the sale to the player is iPago's liability. It is not part of the
  purchase price. See [Tax & VAT](/dev/developer-api/tax).
</Callout>

## Ledger entries

```
GET /v1/ledger_entries
```

For a line-by-line view, list the ledger entries for your store. The list is
[paginated](/dev/developer-api/pagination).

```bash
curl "https://api.ipago.io/v1/ledger_entries?limit=50" \
  -H "Authorization: Bearer sk_live_..."
```

```json
{
  "object": "ledger_entry",
  "id": "le_01M5MWF2T4C0J8B7K2Q9X1VZ3Q",
  "account": "creator_payable",
  "direction": "credit",
  "amount": 939,
  "currency": "eur",
  "transaction": "ltx_01M5MWF2T4C0J8B7K2Q9X1VZ3R",
  "created": "2026-10-23T17:21:05.104Z"
}
```

| Field | Description |
| --- | --- |
| `account` | The ledger account name the API returns today, for example `creator_payable`, `platform_revenue`, `tax_payable`, or `payouts_payable`. These names predate reseller settlement and stay until the ledger change. |
| `direction` | `debit` or `credit`. |
| `amount`, `currency` | The entry's amount in minor units. |
| `transaction` | The ledger transaction (`ltx_`) this entry belongs to. The entries of one transaction always balance. |

A sale is one transaction. The entries of one transaction always balance, so
every cent on this ledger is auditable. The amount iPago owes the supplier is the
purchase price on the weekly invoice, not a reading of `creator_payable` or
`payouts_payable`.
