---
title: Payment methods
description: Which payment methods iPago offers and how a store controls which ones appear.
---

iPago presents buyers the payment methods that are enabled for your store and
eligible for their currency and country. You never touch card data: the hosted
payment form collects and tokenizes it.

## Supported methods

| Key | Method |
| --- | --- |
| `card` | Card |
| `blik` | BLIK |
| `p24` | Przelewy24 |
| `klarna` | Klarna |
| `paypal` | PayPal |
| `ideal` | iDEAL |
| `bancontact` | Bancontact |
| `link` | Link |

The method a buyer used shows up as `payment_method` on the
[order](/dev/developer-api/orders).

## One integration, many methods

Because iPago is the seller to the player, enabling a method is a store setting,
not code. Your [checkout](/dev/checkout/overview) automatically offers the eligible
methods for each buyer, so a new market is a configuration change rather than an
integration.

## Per-store selection

A store can narrow the offered set in the panel (for example, cards and BLIK
only). A store that has not customized the list lets iPago choose the methods per
buyer. Payment methods are not configurable over the Developer API.

<Callout type="info">
  A method only appears if it is both enabled for the store and eligible for the
  buyer's currency and country. Restricting methods too tightly can lower
  conversion for international buyers.
</Callout>
