The **Developer API** is the headless, server-to-server HTTP interface for your
store. It is how your own backend reads what you sell, takes payments, watches
what gets bought, confirms that buyers received what they paid for, and moves
money out through refunds and payouts.

It is built to be predictable: resource-oriented URLs, JSON request and response
bodies, standard HTTP verbs and status codes, bearer-token auth, and the same
conventions on every endpoint.

## What you can do with it

- **Read your catalog.** List and fetch the products and categories you
  configured in the panel.
- **Take payments.** Create a checkout for existing products and mount the
  payment form in your own site.
- **Track sales.** List and fetch orders with their line items, discount, VAT,
  and totals.
- **Manage delivery.** List pending deliveries and mark them completed or failed
  once your system has acted on them.
- **Move money.** Refund an order in full, request a payout of your available
  balance, and read your balance and ledger.
- **Watch disputes.** List chargebacks and their evidence deadlines.
- **Stay in sync.** Read the event log and register webhook endpoints so iPago
  pushes changes to you instead of you polling.

## Scope

This API manages and observes a store whose **products are defined in the
panel**. It is not a toolkit for inventing products in code.

**Available with an API key**

| Area | Endpoints |
| --- | --- |
| Catalog | `GET /v1/products`, `GET /v1/categories` |
| Checkouts | `POST /v1/checkouts` |
| Orders | `GET /v1/orders` |
| Deliveries | `GET /v1/deliveries`, `POST /v1/deliveries/{id}/complete`, `POST /v1/deliveries/{id}/fail` |
| Refunds | `POST /v1/refunds`, `GET /v1/refunds` |
| Payouts | `POST /v1/payouts`, `GET /v1/payouts` |
| Balance and ledger | `GET /v1/balance`, `GET /v1/ledger_entries` |
| Disputes | `GET /v1/disputes` |
| Events and webhooks | `GET /v1/events`, `/v1/webhook_endpoints` |

**Done in the panel, not over this API**

- **Creating or editing products, prices, and categories.** The API references
  products by `id`.
- **Store configuration**: themes, payment methods, tax display, sales, coupons,
  and gift cards.
- **Partial refunds.** The API refunds a whole order. Partial refunds are issued
  by iPago staff.
- **Submitting dispute evidence.** You read disputes over the API and answer them
  in the panel.
- **Bank account details** for payouts.

## The shape of a request

Every call is an HTTPS request to `https://api.ipago.io/v1` carrying a secret key
as a bearer token:

```bash
curl https://api.ipago.io/v1/products \
  -H "Authorization: Bearer sk_live_..."
```

Responses are JSON. Single resources carry an `object` field naming their type;
lists wrap their results in a `{ "object": "list", "data": [...], "has_more": ... }`
envelope.

The machine-readable OpenAPI description of every endpoint is served at
`https://api.ipago.io/openapi.json`.
