---
title: Referrals & commissions
description: Read attributed sales and the commission each affiliate earned.
---

A **referral** is the link between an order and the affiliate who drove it. A
**commission** is what that affiliate earned on it. Both are created by 2Pay when
an attributed purchase completes, following the rates and rules in your panel; the
API reads them.

## The referral object

```json
{
  "object": "referral",
  "id": "ref_01HA0...",
  "affiliate": "aff_01HA0...",
  "order": "ord_01HA0XYZ",
  "code": "ALEX",
  "commission": {
    "object": "commission",
    "id": "com_01HA0...",
    "rate": 0.15,
    "amount": { "amount": 150, "currency": "eur" },
    "status": "pending"
  },
  "created": "2026-06-28T11:42:12Z"
}
```

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Referral id (`ref_`). |
| `affiliate` | string | The attributed affiliate. |
| `order` | string | The order that was referred. |
| `code` | string | The referral code used at purchase. |
| `commission` | object | The earnings, see [below](#commissions). |
| `created` | string | When the referral was recorded. |

## Commissions

The embedded `commission` object describes what was earned:

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Commission id (`com_`). |
| `rate` | number | The fraction applied (for example `0.15` = 15%), from your panel rules. |
| `amount` | object | The earned amount as [money](/dev/developer-api/conventions#money). |
| `status` | string | `pending`, `approved`, `reversed`, or `paid`. |

### Commission status

| Status | Meaning |
| --- | --- |
| `pending` | Recorded, within the hold window (a refund could still reverse it). |
| `approved` | Cleared the hold window; counts toward payout. |
| `reversed` | The underlying order was refunded or disputed; the commission was clawed back. |
| `paid` | Included in a payout to the affiliate. |

<Callout type="info">
  A commission can move from `pending` to `reversed` if the buyer later refunds or
  charges back. Only treat `approved` and `paid` commissions as truly earned.
</Callout>

## List referrals

```
GET /v1/referrals
```

| Parameter | Description |
| --- | --- |
| `affiliate` | Only referrals for one affiliate id. |
| `order` | The referral for a specific order, if any. |
| `status` | Filter by the commission status above. |
| `created[gte]` / `created[lte]` | Time-range filter. |
| `limit`, `starting_after`, `ending_before` | [Pagination](/dev/developer-api/conventions#pagination). |

```bash
curl "https://api.2pay.io/v1/referrals?affiliate=aff_01HA0...&status=approved" \
  -H "Authorization: Bearer sk_live_..."
```

## Retrieve a referral

```
GET /v1/referrals/{id}
```

## Reacting in real time

Subscribe to the [`referral.created`](/dev/webhooks/events) webhook to learn the
moment a sale is attributed, useful for a live affiliate dashboard or to notify
the partner. As always, [verify the signature](/dev/webhooks/verifying-signatures)
and reconcile periodically against `GET /v1/referrals` so a missed webhook never
leaves your totals out of date.

## Building an affiliate dashboard

A typical partner-facing dashboard combines three reads:

1. `GET /v1/affiliates/{id}` for lifetime `stats` (referral count and earnings).
2. `GET /v1/referrals?affiliate={id}` for the per-sale breakdown.
3. Filter by `status=approved` to show cleared earnings versus pending ones.

Because commission `amount` values are [minor-unit integers](/dev/developer-api/conventions#money),
sum them as integers and format for display only at the very end, never store
running totals as floats.
