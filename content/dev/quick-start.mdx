title: Quick start
description: From a fresh account to your first confirmed delivery, end to end.

This guide takes you through a complete integration loop: create a key, read your
catalog, take a payment, and confirm delivery. It assumes you already have an
account and at least one product configured in [app.2pay.gg](https://app.2pay.gg).

## Before you start

You will need:

- A 2Pay account with a store. If you are not there yet, follow
  [Getting started](/creators/getting-started) first.
- **At least one product** created in the panel. The API reads and sells
  products that already exist, it never creates them.
- A backend you control where you can store a secret key safely. Never put a
  secret key in a browser, a mobile app binary, or a public repository.

## 1. Create an API key

In the panel, open **Integration**, pick **Webhooks and Custom API**, and create a
key in the **Developer API** section. Keys come in two modes, chosen with the
Test / Live switch at the top of the page:

- **Test keys** (`sk_test_...`) work on a separate sandbox copy of your store.
  No real money moves. See [Test mode](/dev/developer-api/test-mode).
- **Live keys** (`sk_live_...`) act on your real store.

Build against a test key first, then swap to live when you are happy. For this
guide, give the key the `products:read`, `checkouts:write`, `orders:read`,
`deliveries:read`, and `deliveries:write` scopes.

```bash
export TWOPAY_KEY="sk_test_your_key_here"
```

See [Authentication](/dev/developer-api/authentication) for scopes and rotation.

## 2. Read your catalog

Confirm the key works by listing the products in your store. Every request goes
to `https://api.2pay.gg/v1` and carries your key as a bearer token.

```bash
curl https://api.2pay.gg/v1/products \
  -H "Authorization: Bearer $TWOPAY_KEY"
```

A successful response is a paginated list:

```json
{
  "object": "list",
  "data": [
    {
      "object": "product",
      "id": "prod_01M5MWCZPX3X7V41C1J6Y83TGW",
      "name": "VIP Rank",
      "description": "Permanent VIP rank with cosmetic perks.",
      "active": true,
      "category": null,
      "price": { "amount": 999, "currency": "eur" },
      "type": "single",
      "billing_interval": null,
      "delivery_target": "game_server",
      "image_url": null,
      "created": "2026-10-23T17:19:41.936Z",
      "updated": "2026-10-23T17:19:41.936Z"
    }
  ],
  "has_more": false
}
```

Note the product `id`, you will reference it at checkout. Products live in test
and live mode separately, so a test key only sees test products.

## 3. Let the buyer pay

Pick the surface that fits your product:

- **No frontend, fastest path:** turn on a [Webstore](/dev/webstores/overview)
  and send buyers to your 2Pay subdomain. You are done; skip to step 4.
- **Pay inside your own site or app:** use [Checkout](/dev/checkout/overview).
  Your backend creates a checkout for the chosen products, then your frontend
  mounts the payment form with the returned `client_secret`.

A minimal checkout creation call looks like this. Request bodies are always JSON:

```bash
curl https://api.2pay.gg/v1/checkouts \
  -H "Authorization: Bearer $TWOPAY_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "items": [{ "product": "prod_01M5MWCZPX3X7V41C1J6Y83TGW", "quantity": 1 }],
    "delivery_target": "Notch",
    "country": "DE"
  }'
```

`delivery_target` is the buyer's in-game name (or whatever identifies who
receives the purchase). `country` is the buyer's ISO country code; 2Pay uses it to
compute VAT. The response is `201 Created`:

```json
{
  "object": "checkout",
  "id": "ord_01M5MWDACTVABBZT3E8T2B6QA5",
  "client_secret": "cs_test_..._secret_...",
  "status": "open",
  "total": { "amount": 1189, "currency": "eur" }
}
```

The `id` is the order that this checkout will pay (it starts as `pending`).
`total` is what the buyer will be charged, VAT included. Hand `client_secret` to
your frontend; the browser flow is covered in
[Checkout → Integrating](/dev/checkout/integrating).

In test mode, pay with the Stripe test card `4242 4242 4242 4242`, any future
expiry date, and any CVC.

## 4. Hear about the sale

Do **not** rely on the browser to tell you a payment succeeded; a closed tab or a
dropped connection would lose it. Instead, let 2Pay notify your backend.

Register a webhook endpoint (in the panel under **Integration → Webhooks and
Custom API**) and subscribe to `order.paid` and `delivery.pending`. When the buyer
pays, 2Pay sends a signed `POST` to your URL. The event's `data` is the resource
itself:

```json
{
  "object": "event",
  "id": "evt_01M5MWF2T4C0J8B7K2Q9X1VZ3N",
  "type": "order.paid",
  "created": "2026-10-23T17:21:05.118Z",
  "data": {
    "object": "order",
    "id": "ord_01M5MWDACTVABBZT3E8T2B6QA5",
    "status": "paid",
    "items": [ { "object": "order_item", "id": "oi_01M5MWDACTVABBZT3E8T2B6QA4", "product": "prod_01M5MWCZPX3X7V41C1J6Y83TGW", "name": "VIP Rank", "quantity": 1, "unit_price": { "amount": 999, "currency": "eur" } } ],
    "delivery_target": "Notch"
  }
}
```

The order above is shortened; see [Orders](/dev/developer-api/orders) for every
field. Always verify the `2Pay-Signature` header before trusting the body. See
[Verifying signatures](/dev/webhooks/verifying-signatures).

## 5. Deliver and confirm

Each line item of a paid order gets a **delivery** (`del_...`). How you complete
it depends on what you sell:

- **A game item, rank, or command:** your game server or plugin uses the
  [Game API](/dev/game-api/overview) to pull the queued commands, run them
  in-game, and confirm them. 2Pay then completes the delivery for you.
- **Anything your backend handles directly** (a license key, a role, an account
  flag): find the pending delivery, grant it, then confirm it over the Developer
  API:

```bash
curl "https://api.2pay.gg/v1/deliveries?status=pending" \
  -H "Authorization: Bearer $TWOPAY_KEY"

curl -X POST https://api.2pay.gg/v1/deliveries/del_01M5MWF2T4C0J8B7K2Q9X1VZ3P/complete \
  -H "Authorization: Bearer $TWOPAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "note": "Granted VIP to Notch" }'
```

Once confirmed, 2Pay emits `delivery.completed`.
